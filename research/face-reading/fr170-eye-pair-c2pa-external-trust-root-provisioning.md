# FR170 — Eye-Pair C2PA External Trust-Root Provisioning and Conforming Generator Profile

## Status

**Pinned external C2PA trust-root provisioning may succeed only against an immutable C2PA-governed snapshot. No participant witness credential or independent session is admitted by FR170.**

FR169 froze the admission requirements but intentionally left `actualTrustRootProvisioned=false` because no independently governed root/verifier had been selected. This source is not generated by the Saju repository, the participant, or the runtime caller. The exact commit and Git blob identities are pinned before any future authority-promotable capture.

The pinned trust-list snapshot declares:

- scheme name `C2PA Trust List`;
- scheme operator `C2PA - Coalition for Content Provenance and Authenticity`;
- scheme information URI `https://c2pa.org/conformance`;
- issue time `2026-08-05T00:11:39Z`;
- next-update time `2027-08-05T00:11:39Z`;
- trusted services carrying X.509 trust material.

The pinned conforming-products snapshot contains conformant generator profiles for both `Proofmode for Android` and `Proofmode for iOS`, operated by `Proofmode Reality Systems LLC`, with JPEG generation capability.

## Exact-byte and semantic verification

FR170 does not trust a URL, opaque reference, or caller boolean. Runtime success requires the supplied external bytes themselves to reconstruct the exact Git object IDs pinned above.

After exact byte identity succeeds, the runtime also performs bounded semantic verification:

1. parse the trust-list JSON;
2. verify scheme name, scheme operator, and scheme URI;
3. parse issue/next-update times and confirm the repository-governed evaluation instant is within the window;
4. identify services whose C2PA trust-list status is `trusted`;
5. decode and parse X.509 certificates for those trusted services;
6. require at least one CA certificate and supported public-key formats;
7. parse the conforming-products snapshot;
8. verify conformant Proofmode Android and iOS generator profiles;
9. verify JPEG generation capability for both profiles;
10. bind the exact trust-list bytes back to the FR168 digest carried through the actively issued FR169 predecessor.

A caller-created JSON document that merely copies the expected fields fails because its Git blob identity does not match the immutable external snapshot.

FR170 separates **root/path provisioning** from **participant-media witness admission**.

The following may become true after successful exact external verification:

Here `trustRootRevocationStatusVerifiedForPinnedSnapshot` means that the exact pinned governance snapshot was semantically evaluated using its C2PA trust-list service-status model. It does **not** claim that a future participant-media leaf credential has already passed OCSP/CRL/status evaluation.

Likewise, `signerChainPolicyVerifiedForProspectivePath` and `semanticTrustEvidenceVerifierGoverned` mean that the prospective path is fixed to C2PA Content Credentials validation against the pinned C2PA trust material. They do **not** mean a participant-media signer chain has already been validated.

`captureToWitnessBindingMechanismRequiredAndGoverned=true` is a provisioning property. The per-media fact remains false until a newly captured Content Credential is actually validated.

## Prospective-only collection boundary

Sessions 1–3 from FR163–FR165 remain non-retroactively-promotable.

After FR170, the next authority step requires genuinely new media produced after this governance path was pinned. Ordinary camera files are not authority-promotable under this path. The source media must retain its original C2PA Content Credential generated by the pinned conforming-generator class, followed by manifest, signer-chain, trust, and capture/content-binding verification.

## Privacy boundary

FR170 transiently accepts only the external C2PA Trust List bytes and Conforming Products List bytes. Those external governance files are not copied into the issued result.

FR170 accepts and persists no participant image, provider response, landmark set, derived face geometry, participant measurement, source-image digest, exact capture timestamp, geolocation, device identifier, face embedding, or identity template.

## Dedicated CI evidence

The dedicated FR170 workflow downloads both external files from the immutable external commit rather than from a moving branch. The FR170 runtime itself recomputes their Git blob object IDs and performs semantic verification before the live success path can pass.

This distinguishes external authority verification from a synthetic fixture: synthetic fixtures remain useful only for fail-closed tests and cannot produce `actualTrustRootProvisioned=true`.
