# 다국어 사주 용어·상태 메시지 리소스 — E-4 첫 구현

> 2026-10-22 / [12메뉴 로드맵](../ROADMAP.md) 공통 E 작업선. 기존 Claim/Rule/해석 권한 변경 없음.
> 기반: [Reading On-Demand 설계](./saju-multilingual-reading-on-demand-design-v1.md), `CanonicalReadingSemanticBundleV1`.

## 구현

- `src/reading/reading-locale-lexicon.ts`는 사용자에게 보여줄 *정적인 명리 용어 및 읽기 상태 메시지*만 locale별로 관리한다. **사용자별 사주 해석 문장 생성·번역은 하지 않는다.**
- 고정 개념 키: 사주·년주·월주·일주·시주·일간·십신·대운. 로케일별 display 문구는 키에만 매핑하며 학파별 의미·판단은 추가하지 않는다.
- 응답 메시지 키: 기존 `ProductReadingResponseMessageCode`의 9가지 상태를 모두 유지한다. 상태별 영어/한국어 일반 안내 문구는 서로 다른 의미 판정을 추가하지 않는다.
- 등록됨: `ko-KR`, `en-US`의 **용어 및 읽기 상태 메시지만**. 등록되지 않은 `ja-JP`, `zh-CN`, `zh-TW`, `vi-VN`, `ms-MY`, `id-ID`는 로케일 카탈로그에 있어도 해당 용어집/상태 메시지를 생성하지 않는다. 자동 영어/한국어 대체 표시 없음.
- 내용 해시와 용어집 버전은 캐시 분리에 사용 가능하며, 누락·여분 개념 키 또는 빈 번역 문자열을 리소스 구성 단계에서 거절한다.
- 소비자-facing UI 전역 버튼/메뉴 라벨, 화면 언어 선택, 언어별 배포 조건은 MyeongHa UX 제품 트랙이 책임진다. 이 코드는 Saju 엔진이 소유한 구조적 용어/상태 안내에 국한된다.

## 반드시 구분

1. **로케일 카탈로그 등록**: 다국어 계약이 이해하는 로케일 식별자.
2. **용어집 등록**: 정적 용어와 상태 메시지가 존재한다는 것.
3. **개인별 해석 Renderer 승인**: 해당 로케일의 실제 출생 입력에 근거한 개인별 문장 출력과 Claim/Qualifier/HOLD 보존.
4. **제품 공개·판매 승인**: 별도 기존 권한 및 상용화 게이트.

현재 구현된 것은 2번의 `ko-KR`·`en-US`까지만이다. 특히 **영어 개인별 해석은 아직 구현되지 않았다**.

## 남은 E-4 및 E-5

- 다른 6개 로케일에 대한 검토된 용어 사전 및 정적 상태 안내 문구 추가
- 단수/복수, 언어별 조사·단어 순서·연령/호칭·문화권 텍스트 규칙 등 UI/Reader 표현 정책
- 영어부터 실제 Claim·Evidence 기반 On-Demand Renderer와 텍스트 의미 보존/불확실성 처리 구현
- 한국어 기존 서비스 연동 및 캐시/접근 권한/보관·삭제는 해당 소유 경로에서 구현
