# P0-NATAL N22 — 실제 명식의 기존 T8 관계를 한 화면에서 읽기

**상태: 내부 시제품 전용 / Research-HOLD / 외부 전문가 심사 대기 없이 기능 개발 진행**

## 해결하는 문제

N13~N20의 개별·연결·상반된 십신 구조 후보는 실제 명식을 계산하고 T5/T8 Claim 출처를 확인한 결과지만, 별도의 연구 패킷에서만 읽을 수 있었다. N21은 다섯 도메인의 Preview 원문을 읽기 쉽게 보여줬으나 이 *실제 명식에서 실행된 연구용 관계들*은 사용자용 내부 HTML에서 바로 확인할 수 없었다.

## 구현

- 새로운 규칙/주장/원전 문장 없이 기존 N13(개별 T8), N14/N19(연결된 생성 관계), N20(서로 다른 관계 종류의 공존) 생성기를 그대로 사용한다.
- `buildNatalN22ChartRelationGuide`는 **같은 Canonical snapshot**에서 별도의 *research-only* source-bounded registry를 실행한 결과를 받는다. 스냅샷·계산 hash, 연구 registry, 원래 T8·T5 Claim, 실제 위치 경로 및 문헌 locator를 검증한다.
- 내부 HTML의 **핵심 사주풀이(N21) 뒤**에 '내 명식에서 확인된 십신 관계'를 추가한다. 관측된 연결 관계 → 서로 다른 방향의 관계 → 개별 T8 순서로 보여주고, 각각 원래 Claim·계산 fact path·문헌 locator를 펼쳐 확인할 수 있도록 한다.
- 실제로 없는 관계는 표시하지 않는다. **출생시간 미상은 N13의 완전 명식 전제를 건너뛰지 않고 `birth_time_unknown`으로 보류한다.**
- 단순히 식상/재성 등의 존재를 확인한 것과 T8 규칙이 실제 실행된 것은 엄격히 구분한다.
- 기존 다섯 도메인의 Preview 문장, N21 내용, Calculation/Official Reading/Production, 공개 및 결제는 **변경하지 않는다**.

## 검증 기준

- 정확한 T8 Claim 2개와 독립 T5 3개를 가진 관계만 연결해 보여준다. 원문 locator 두 개 이상과 실제 명식에서 계산된 십신 위치가 있어야 한다.
- 단순 비견은 겁재 조건 관계로 승격되지 않는다. 한쪽 계열이 없는 경우 관계를 만들어 채우지 않는다.
- 실제 명식에서 결과물이 결정적이어야 하며 다른 명식/registry를 바꿔치기하면 거부해야 한다.
- 출생시각 미상 사례는 시주 관련 관계를 임의로 확정하지 않는다.
- CI에서는 원래 내부 HTML을 직접 생성하고 제목·연구 경계 표기를 확인한다.
- **전문가 심사를 요구하지 않고 내부 시제품을 계속 개선한다.** 다만 기존 공식 배포/판매 권한의 제한은 별도이며 이 작업에서 바꾸지 않는다.

**P0-NATAL 전체 미완료.** 더 많은 사주 계산/의미 후보를 화면에 보이는 결과물로 실제 연결했지만, 관측 관계가 현실의 부·진로·성격이나 길흉을 결정한다는 근거로 주장하지 않는다.
