# P0-NATAL N21 — 실제 개인별 읽기 흐름 우선 배치

**2026-10-16 · 내부 Preview UX · 실사용 가능한 풀이 배치 개선.**

## 문제

N16~N20까지 기존 계산·해석·구조 관측 결과의 추적 기능은 늘었지만, 단일 시제품 페이지에는 같은 개인의 풀이 원문, 구조 계산 설명, 개별 연구 테마, 적용 테마가 여러 차례 반복된다. 이를 처음 읽는 사용자에게 노출하면 핵심 풀이가 묻힌다.

현행 P0-NATAL 성공 기준은 새 문장 개수가 아니라 **실제 생년월일 → 명식 → 설명 → 근거 → 이해할 수 있는 개인별 결과**다. 원문 증거를 버리지 않고, 읽는 순서를 고친다.

## N21 실제 구현

- `buildNatalN21ReaderFirstStory(snapshot, sources)`는 실제 5개 HTTP Preview 도메인 응답을 N16의 기존 보호 게이트로 다시 검사한다. 출생정보/시간/시주/명식 표시가 다르면 실패한다.
- **내 사주풀이, 핵심부터 읽기**를 화면 가장 앞에 표시한다. 실제 계산된 일간·연월일시·십신 위치는 별도 *계산 근거*, 5개 도메인의 해석 문장은 *실제 Preview 원문*으로 명확하게 나눠 표시한다.
- 일반 원국→직업→재물→사업→관계 순서로 **분야별 전달된 원문 최대 3개**를 그대로 보여준다. 있는 그대로의 문장을 편집하거나 다른 생년월일에 맞춰 끼워 넣지 않는다.
- 이미 앞 도메인에서 보인 동일 문장은 다시 출력하지 않고 반복 사실만 알려준다. 나머지 기존 문장·원문 응답·해석 한계·연구용 부록은 펼침 영역에서 모두 유지한다.
- 시각 미상 또는 실제 응답이 `partial_evidence`인 분야는 새 풀이로 채우지 않는다. 원래 응답 상태를 명확히 표시한다.
- 분리 계량: 독자가 실제 읽는 기존 해석 문장 수, 중복 생략 수, 명식 계산 사실 문장 수, 기존 문장만 기반으로 한 fingerprint. 사실 문장만 달라진 것을 해석 차별성으로 절대 세지 않는다.
- 기존 명식 계산, Rule Registry, InterpretationClaim/Preview 승인/Production/Release/Commerce, 문장 원문 의미는 변경하지 않는다.

## 검증

- 경량 단위 테스트: 실제 Canonical 명식에서 5도메인 원문 순서, 중복 숨김, 출처·본문 원문 일치, N5/N7 계산설명 분리, 실제 서로 다른 명식에서 동일 해석 fingerprint, 시간 미상/부분 응답, 명식 위조, N5 표식 악용, 결정성.
- 기존 35개 실제 General Natal HTTP 회귀에 N21 결과를 **동일 응답을 재사용하여** 추가한다. 연구 의미 차별성이나 Production 승인으로 오해하지 않는 별도 JSON을 CI 산출물로 저장한다.
- 기존 N16/17 품질 감사와 원문 5도메인 HTML 모두 유지한다.

## 한계와 다음 품질 단계

개별 도메인에서 실제로 허용된 기존 해석 문장을 읽기 쉽게 조립한 것이지, 이전에 없던 깊은 사주 의미를 발굴한 것은 아니다. 사용자 평가 없이 의미 품질 개선 완료를 선언하지 않는다.

다음 우선순위는 실제 샘플 명식의 **진짜 해석 내용·중복·모순**을 자동 비교하고, 내부 시제품에서 반복되는 막연한 테마 대신 **이미 근거/권한이 있는 구체적 하위 십신·실제 활성화된 조건**을 사용해 주장별로 필요한 경우에만 풀이를 더 좁히는 것이다. 외부 전문가 심사 대기를 내부 제품 개발의 선행 조건으로 삼지 않는다. 단, Review/Production/Commerce의 기존 승격 제한은 우회하지 않는다.

**P0-NATAL 제품 목표는 미완료**이며, N21은 보이는 실제 해석의 전달 품질 개선이다.
