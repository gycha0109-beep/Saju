# P0-NATAL N6 — 계산정보 차이와 풀이 의미 차이를 분리하는 품질검사

작성일: 2026-10-15
적용 범위: **General Natal 내부 Preview**. 신규 명리 판단/출시/판매 승인 아님.

## 문제가 된 성공지표

실제 출생정보 35건(시간 있는 32 + 시간 미상 2 + 동일 입력 재검증 1)을 기존 사주풀이 HTTP 경로에 넣었다.

- N3 단계: 사용자에게 전달된 기존 해석 본문 27종, 서로 다른 명식인데 동일 해석 본문이 나온 경고 6쌍.
- N4 단계: 이 6쌍 모두 내부 연구 테마 관측 위치가 달라지는 사례임을 확인했다.
- N5 단계: 계산된 연/월/일/시주를 실제 일반 사주풀이 본문에 연결했다. 사용자가 받는 전체 문장 지문은 32종이고 기존의 6쌍이 서로 구분된다.
- **단, 계산된 명식 문구만 추가해도 전체 텍스트 지문은 달라진다. 0건을 '해석 내용이 0건 중복'으로 해석하는 것은 오류다.**

## N6 수행 내용

1. `buildNatalMeaningQualityAudit`: 실제 consumer output을 그대로 유지한 전체 본문 지문과, **N5의 명식 계산 문단만** 제거한 해석 의미 지문을 동시에 비교한다. 기존 해석 문구와 불확실성 상태는 수정하지 않는다.
2. 출생정보 35건으로 다음을 각각 검증한다:
   - 전체 소비자 출력 지문 고유성
   - **계산 문구를 제외한 기존 해석 본문 지문 고유성**
   - 서로 다른 명식인데 풀이 의미가 중복된 쌍
   - 명식 계산 문구 때문에 *겉으로만* 차별화된 쌍
3. `natal-baseline.meaning.json` 추가. N3의 연구 규칙 비교도 전체 텍스트가 아닌 의미-only 지문과 다시 연결한다. 원래 규칙 구분력 부족/출력 조합 문제의 3쌍+3쌍 진단을 복구한다.
4. N6 출력의 `semanticCompletionGranted`는 언제나 `false`. 검사 강화만으로 새로운 해석 권한을 부여하지 않는다.
5. 생성된 계산 문단이 반복되거나 잘못된 내용이 계산 문단처럼 위장되어 있으면 거부한다.

## 검증과 다음 단계

- TypeScript, Lint, Build, 전체 테스트, 실제 35건 HTTP 감사, SHA 고정 통합검증.
- 현재 N6는 **의미 중복 6쌍을 남은 과제로 정확히 드러내는 단계**다. 사주풀이가 완성됐다고 주장하지 않는다.
- 그중 실제 Research 매칭 규칙이 달랐던 **3쌍**은 기존 T8 해석이 어떤 경로에서 빠지는지 `claim → semantic unit → ReadingPlan → renderer`에 연결된 근거를 비교해 원인을 해결한다. 연구 규칙이 동일했던 나머지 **3쌍**은 [연구 이슈 #2529](https://github.com/gycha0109-beep/Saju/issues/2529)의 근거 판정이 필요하다.
- 새 의미를 생성하는 개선은 기존 Official Reading 승인 경로에서 별도 심사한다.
