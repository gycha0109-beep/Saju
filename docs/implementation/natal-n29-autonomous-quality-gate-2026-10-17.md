# N29 — 실제 35명식 / 고유 19쌍 자율 품질 검증 1차 게이트

2026-10-17 · Watchtower-Track: saju · 내부 Preview 품질 검증

## 목적과 범위

N27a/b와 N28a를 통과한 출력이 **실제 HTTP 원본 35건**과 출처·계산·보고서까지 연속적으로 일치하는지 검사한다.
기존 N10의 반복 명식 비교 20쌍은 동일 입력 대조군을 중복 계산하지 않고 **고유 명식 쌍 19개**로 따로 센다.
명식별 문장 차이는 십신의 실제 위치와 기존 Claim/Rule/Source에 연결된 차이만 인정하며, 무조건 다른 운세를 만들지 않는다.

## 새 자동 게이트

- `scripts/natal-n29-autonomous-quality-gate.mjs`: 기존 감사에서 **실제 실행해 만든** HTTP·N10·N26·N27a·N27b·N28 자료를 독립 입력으로 상호 대조한다.
- `test/natal-n29-autonomous-quality-gate.node.mjs`: 동일 명식의 불필요한 문장 차이, 잘못된 십신 위치, 출처 누락, 임의의 소비자 본문, 출생시각 미상 결과의 과잉 승격, HTTP 의미 전달 손실을 음성 사례로 막는다.
- 기존 CI Quality 흐름에서 실제 감사 자료 생성 직후 이 게이트를 실행한다. 작업 단계별 별도 GitHub Actions Workflow를 만들지 않는다.

## 판정의 범위

1. 동일 입력·동일 판본에서는 독해·영수증·사용자 보고서가 동일해야 한다.
2. 서로 다른 명식 사이에 **실제로 소비된 Claim/십신 위치**가 달라지면, 독해 내용도 해당 근거를 보존해야 한다.
3. 소비된 Claim/위치/출처 근거가 같으면 억지로 문장을 다르게 만들어서는 안 된다.
4. 기존 Official 해석 원문과 Reading 식별자, HTTP 전달 의미는 보존한다.
5. 출생시각 미상인 2건은 근거 없는 시주와 확정 개인 해석을 생성하지 않는다.
6. 기존 고전 경합 의미와 새 인간 행동·금전 결과 추론은 이 게이트를 통과해도 승인되지 않는다.

## 남는 한계

이 검사는 **계산·Claim·출처·표시 문장 간 무결성**과 재현성에 대한 1차 기계적 검증이다.
전통 명리 풀이가 실제 인생 결과를 예측한다는 실증적 증거도, 사용자의 체감 가치가 충분하다는 독립 평가도 아니다.
N29 전체 및 P0-NATAL은 **미완료**이며 `usefulComplete:false`와 Production/Commerce HOLD는 유지한다.
