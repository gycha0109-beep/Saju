# P0-NATAL N23 — 실제 다섯 분야의 고유 풀이를 먼저 읽기

**2026-10-17 · 내부 Preview UX / 기존 허용 해석 원문 우선순위 보정.**

## 확인된 결함

N21 독자 우선 보고서의 각 분야는 원래 전달된 해석 중 **처음 3개**를 그대로 선정한다. 그런데 일반/직업/재물/사업/관계가 동일한 설명을 반복할 때 공통 문장들이 지면을 먼저 차지하면, 실제로 그 분야만의 문장은 접힌 상세로 내려간다. 이는 사주풀이가 부실해 보이거나, 다른 분야를 읽어도 같은 내용이 반복되는 실제 UX 문제다.

## 구현

- N16이 이미 검증한 **실제 HTTP 응답의 원문/출처**, 명식/생년월일 일치 검사, N18의 계산 설명과 해석 구분을 그대로 사용한다.
- N23 `domain-distinctive-source-reading-selection-v1`: 각 분야의 풀이 후보를 두 그룹으로 나눈다. **해당 분야 응답에만 있는 원문**을 원래 순서대로 우선 선택하고, 3개의 슬롯에 자리가 남으면 **여러 분야에서 반복되는 원문**을 추가한다.
- 표시하지 않은 다른 원문, 중복된 원문, 계산 사실은 삭제하지 않는다. 전체 원문 펼침과 출처 추적은 그대로 유지한다.
- 문장 원문과 Preview meaning fingerprint는 **변경하지 않는다**. 표시 순서를 의미의 중요성/강약/실효성 또는 독립된 개인화 의미로 오인하지 않도록 '이 분야에만 전달된 풀이'와 '여러 분야에서 공유된 풀이'로만 표시한다.
- 화면과 JSON에 *보인 고유 문장 / 보인 공유 문장 / 앞에서 보인 중복 / 접힌 원문*을 따로 세어, 가짜 개인화 숫자를 방지한다.
- 사용자에게 아직 실제 해석 문장이 없는 분야나 출생시각 미상은 기존대로 비워 둔다.

## 검증

- 실제 Canonical 명식 기반 5도메인 bounded Preview 테스트에서 선행 공유 문장 때문에 직업 분야 고유 해석이 사라지지 않는지 확인한다.
- 다른 분야에 이미 화면 표시한 문장은 두 번째 화면에 중복하지 않는다.
- 기존 N5/N7 계산 전용 문구를 고유 해석으로 세지 않는다.
- 원문 출처/허용 범위/명식 일치 및 Preview/Production/Commerce 경계를 변경하지 않는다.
- 35개 HTTP 기준 케이스는 주로 General 단일 도메인이다. 여기서 공유 문장 0이라는 사실은 다섯 도메인에서 반복이 없다는 근거가 **아니다**. 다섯 도메인 동작은 별도 E2E 및 단위 테스트로 확인한다.

## 남는 제품 과제

35개 실제 General Preview에서 N6 집계의 서로 다른 명식과 같은 의미의 경우는 본 작업으로 해결되지 않는다. 다음 단계는 **원문 의미를 가짜로 늘리지 않고, 허용된 Claim의 실제 하위 조건/근거와 사용자별 풀이 문장을 정합하게 연결하는 것**이다.

**P0-NATAL 완료 판정: 아직 미완료.** 외부 전문가 심사 대기를 내부 UX 개발의 장애물로 두지 않지만, 내부 실험이 공식 의미 승인이나 판매 허가를 대체하지는 않는다.
