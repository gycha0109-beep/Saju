# P0-NATAL N11 — 실제 HTTP 사주풀이 10건 사람 검수 패킷

**범위:** `docs/ROADMAP.md`의 N5 실제 소비자 읽기·사람 검수 증거 준비. 별도의 의미 승인/규칙 구현이 아니다.

## 재현 방법

기존 `scripts/natal-personalization-audit.mjs` 실행 후 `natal-baseline.n11-review.html` 생성.
사용자가 받게 되는 **실제 35건 HTTP Preview 응답을 그대로 소스로** 하여 10개 대표 사례의 계산 요약, 실제 사용자 본문, disclosure, delivery state를 읽을 수 있게 한다. 오프라인 출력도 가능하며 코드가 생성한 것은 **검수 양식**이지 검수 결과가 아니다.

10건: 1984-01-07 00:30/12:30(관성 channel), 1989-09-08 05:30/12:30(십신 family 차이), 같은 날짜 00:30/19:30(관측 유무), 1992-01-12 00:30/19:30(같은 Research rule signature), 출생시간 미상 1992-01-12/2024-03-10(부분/차단 응답). 총 **정상 delivery 8건 / 부분 근거 2건**.

- 사용자가 보게 되는 문구를 인위적으로 요약하거나 개선해 표현하지 않는다.
- `source_hint`, 각 도메인 섹션, 제한/근거 안내 등 실제 블록을 그대로 출력한다.
- 내부 Claim/semantic/plan/chart fact를 이용해 새 판단을 추가하지 않는다.
- 출력에서 HTML 이스케이프 처리하고 유효한 35건 세트·선정 caseId·응답 상태를 강제한다.
- 자동 테스트와 CI artifact 업로드로 리뷰 대상의 재현성을 보장한다.

## 사람이 실제로 평가할 항목 (모두 미완료)

1. 계산 사실이 입력·명식·시간 불확실성과 일치하는가?
2. 사용자용 해석 문장이 실제 출처/승인 범위를 넘는가?
3. 명식별 구조 차이를 실제 의미 변화에 정당하게 반영했는가, 또는 동일한 해석이 정당한가?
4. 보고서 안의 중복·논리적 모순·어색한 표현은 없는가?
5. 일반 사용자 가독성, 안전한 한계/미상 처리, 과잉 확신 문제가 있는가?

**사람의 검수자 이름·검수 일시·각 사례별 인용 및 판정·정정 의사결정이 없다면 N5 review gate는 열지 않는다.** 생성 과정만으로 검수 완료/출시 승인/판매 승인/일반 원국 종합 사주풀이 완성을 주장하지 않는다.

참조: #2535, #2529 및 N10 품질 파일. N8/N9/N10의 19개 고유 명식 해석 중복 경고와 의미 승인 HOLD는 계속 유효하다.
