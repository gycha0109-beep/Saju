# 12. Reading Profile Content Authorization Contract

## 1. Purpose

This stage separates two concepts that must not be conflated:

```text
DomainReadingProfile exists
!=
DomainReadingProfile is authorized for runtime evidence selection
```

The previous ReadingIntent stage introduced deterministic profile definitions that map consumer reading requests to selectors over already-existing InterpretationClaims. This stage adds an exact, content-addressed authorization gate for those selector profiles.

The authorization scope is intentionally narrow:

```text
reading evidence selection only
```

It does not authorize interpretation semantics, claim generation, research promotion, domain meaning, shinsal, pillar-domain projection, or any production interpretation rule.

---

## 2. Runtime boundary

Public package runtime:

```text
ReadingRequest
  -> ReadingIntent
  -> resolveDomainReadingProfile()
  -> profileRef { id, version, contentHash }
  -> Reading Profile Selection Authorization Gate
  -> existing intent composition
  -> existing Narrative Evidence Selector
  -> NarrativeEvidenceBundle
```

The package root exports the governed `buildReadingCompositionEvidence()` wrapper. The earlier composition implementation remains an internal implementation substrate and is no longer re-exported as the public package entry point.

---

## 3. Exact content authorization

Authorization is bound to all three fields:

```text
profileId
profileVersion
profileContentHash
```

A matching id/version with a different content hash is not accepted as the same authorized profile.

Possible authorization states:

```text
authorized
not_authorized
content_mismatch
```

`content_mismatch` is fail-closed. Changing a selector, exclusion, required group, temporal requirement, ambiguity policy, conflict policy, or completeness policy changes the profile hash and therefore requires a new explicit authorization record.

---

## 4. Frozen v1 authorization set

The current authorization set contains the exact v1 profile contents for the 19 already-defined intent shapes:

- general natal / annual / monthly
- family parents / children
- relationship general / spouse
- compatibility natal
- career natal / annual / monthly
- business natal / annual / monthly
- wealth natal / annual / monthly
- life-stage general
- question-specific natal

This authorization set does not assert that matching T8/T9/T10/T11 claims currently exist. A profile may be authorized for selection and still produce:

```text
partial_coverage
insufficient_evidence
unsupported_intent
```

No missing claim may be generated by the reading layer.

---

## 5. Authorization record

Each exact profile content is bound to a `ReadingProfileSelectionAuthorization` with:

```text
decision = authorized_for_selection
scope    = reading_evidence_selection_only
```

Hard constraints:

```text
mayAuthorizeInterpretationRules      = false
mayAuthorizeClaimGeneration          = false
mayAuthorizeDomainSemantics          = false
mayPromoteResearchAuthority          = false
mayOverrideInterpretationAuthorization = false
```

The authorization record is itself content-addressed and its reference is bound into the governed reading selection identity.

Therefore selection determinism is based on the existing deterministic inputs plus the explicit authorization policy/content binding.

---

## 6. Authority non-equivalences

The following are mandatory:

```text
Reading profile authorization
!= interpretation rule authorization

Reading profile authorization
!= domain semantic authority

Reading profile authorization
!= claim creation authority

Reading profile authorization
!= provenance promotion

Reading profile authorization
!= source admissibility

Reading profile authorization
!= T7 shinsal activation

Reading profile authorization
!= pillar-domain projection activation
```

The profile only determines which already-authorized, already-existing claims are eligible to be selected for a consumer reading request.

## 9. Failure behavior

If the intent shape has no profile:

```text
coverageState = unsupported_intent
profileAuthorization.state = not_authorized
```

If profile id/version is known but profile content differs from the frozen authorization record:

```text
coverageState = unsupported_intent
profileAuthorization.state = content_mismatch
missingRequirements = [READING_PROFILE_CONTENT_HASH_NOT_AUTHORIZED]
```

No NarrativeEvidenceBundle is produced in the profile-authorization failure path.

An authorized profile does not override request-shape requirements. For example, question-specific reading without actual question text remains `unsupported_intent` even though the underlying question-specific profile content is authorized.
