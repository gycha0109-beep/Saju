# Official Reading Detailed Material Authority Contract v1

## 1. 목적

이 문서는 공식 사주 해석의 **상세형 출력이 사용할 수 있는 추가 설명 재료의 권한 계약**을 정의한다.

현재 런타임은 상세형 요청을 기본형으로 안전 대체한다.

```text
detailed request
→ standard fallback
→ missing expansion material
```

이 문서의 병합만으로 위 동작을 바꾸지 않는다.

이번 단계의 목적은 실제 상세 문장을 늘리는 것이 아니라, 이후 구현이 사용할 수 있는 설명 재료와 사용할 수 없는 설명 재료를 먼저 고정하는 것이다.

---

## 2. 비가역 원칙

상세도는 의미 선택기가 아니다.

간결형·기본형·상세형 사이에서 다음은 동일해야 한다.

- 정규 의미 단위
- 해석 순서
- 근거 연결
- 분기 상황
- 상충 관계
- 필수 조건
- 제한
- 의미 소유권
- 출처 연결

상세형은 새로운 사주 의미를 생성하지 않는다.

```text
standard meaning
+ governed explanatory material
= detailed presentation
```

다음 구조는 금지한다.

```text
standard text
→ LLM "더 자세히"
→ new explanation
```

---

## 3. 현재 권한 기반

현재 상세형 설계는 새 병렬 해석 계층을 만들지 않는다.

기존 공식 경로를 그대로 사용한다.

```text
Canonical Saju Snapshot
→ governed Interpretation Claims
→ Canonical Reading Semantics
→ Official Reading Plan
→ Official Reading Renderer
```

상세형의 추가 설명 재료는 **이미 허용된 정규 의미에 종속된 표현 재료**여야 한다.

새 주장, 새 방법론, 새 점수, 새 미래 예측을 소유할 수 없다.

---

## 4. 설명 재료 분류

### 4.1 정규 의미 본문 — 직접 사용 가능

각 사용자 노출 핵심 의미 단위의 현재 정규 문구는 상세형의 기준 문장으로 사용할 수 있다.

조건:

- 현재 정규 의미와 정확히 연결되어 있어야 한다.
- 현재 의미의 순서와 개수를 바꾸지 않는다.
- 상세형 때문에 의미 단위를 합치거나 삭제하지 않는다.

이 재료는 상세형의 "추가 설명" 자체가 아니라 기준점이다.

### 4.2 조건·한정 설명 — 승인 문구가 있을 때만 사용 가능

현재 정규 의미에 연결된 조건 또는 한정 정보가 존재하더라도 내부 구조 값만 보고 사용자 문장을 새로 만들 수 없다.

사용 가능한 경우:

- 해당 조건/한정에 사용자 노출 가능한 승인 문구가 존재한다.
- 현재 정규 의미와 연결이 명시적이다.
- 근거 추적과 현재성 검증이 가능하다.

사용 불가:

- 내부 조건 키만 존재
- 내부 분류값만 존재
- 코드가 조건의 의미를 추론해 설명문을 생성

### 4.3 적용 한계 — 승인 문구가 있을 때만 사용 가능

상세형은 기본형보다 적용 범위와 한계를 더 명확히 설명할 수 있다.

단, 기계용 금지 확장 목록 자체를 사용자 문장으로 변환하면 안 된다.

```text
prohibited extension flag
!= consumer explanation
```

사용자용 적용 한계는 별도 승인 문구가 있어야 한다.

### 4.4 "왜 이렇게 해석되는가" — 현재 자동 생성 금지

방법론 참조, 규칙 참조, 사실 참조, 상위 주장 참조가 존재한다는 이유만으로 사용자용 인과 설명을 만들 수 없다.

```text
ruleRefs / factRefs / methodologyRef
!= approved explanation prose
```

향후 이 재료를 상세형에 사용하려면 다음이 필요하다.

- source-owned 설명 문구
- 어떤 정규 의미를 설명하는지 명시적 연결
- 출처/검토 상태
- 현재성 기준
- 금지 확장

이 권한이 없는 동안에는 상세형 이유 설명에 사용하지 않는다.

### 4.5 구조적 근거 설명 — 현재 자동 생성 금지

정규 사실이나 근거 식별자를 나열하는 것과 사용자가 읽는 설명은 다르다.

구조적 근거를 설명하려면 별도 승인된 표현 재료가 필요하다.

내부 근거 객체를 자연어로 즉석 변환하지 않는다.

### 4.6 분기 상황별 차이 — 보존 가능, 새 비교 설명은 승인 필요

분기 상황은 상세형에서도 그대로 보존한다.

허용:

- 각 분기에 이미 승인된 정규 의미를 그대로 보여주기
- 각 분기에 별도 승인된 설명 재료가 있으면 함께 보여주기

금지:

- 분기 중 하나를 정답으로 선택
- 여러 분기를 평균내기
- 분기 관계를 근거 없이 인과 설명으로 만들기

분기 차이에 대한 별도 비교 문장은 별도 승인 재료가 있을 때만 사용한다.

### 4.7 상충 관계 — 모든 관점 보존, 승자 결정 금지

상충 관계가 존재하면 상세형도 양쪽 의미를 모두 유지한다.

관계 메타데이터만 보고 다음을 만들 수 없다.

- 어느 쪽이 더 강한지
- 어느 쪽이 실제로 우세한지
- 최종 결론이 무엇인지

상충 관계를 설명하는 추가 문구도 승인 재료가 필요하다.

### 4.8 출처 요약 — 기존 선택 기능으로만 사용

출처 요약은 상세형의 자동 구성 요소가 아니다.

```text
detailed
!= include source summaries
```

사용자가 출처 요약을 별도로 요청했고, 등록된 출처 요약이 존재하는 경우에만 기존 규칙대로 표시한다.

상세형 요청만으로 출처 요약을 자동 활성화하지 않는다.

---

## 5. 향후 승인 상세 재료의 최소 계약

후속 구현에서 상세형 승인 재료를 등록하려면 최소 다음 정보를 소유해야 한다.

```ts
interface OfficialReadingDetailedMaterialDefinitionV1 {
  materialId: string;
  domainKey: string;
  targetSemanticKey: string;

  role:
    | 'clarification'
    | 'condition'
    | 'boundary'
    | 'rationale'
    | 'structural_evidence'
    | 'scenario_note'
    | 'tension_note';

  approvedText: string;

  baseline: {
    canonicalMeaningHash: string;
    qualifierStateHash: string;
    limitationStateHash: string;
  };

  provenance: {
    authorityId: string;
    authorityVersion: string;
    sourceRefs: readonly string[];
  };

  prohibitedExtensions: readonly string[];
}
```

이 모양은 후속 구현의 정확한 TypeScript 이름을 고정하는 것이 아니다.

고정하는 것은 다음 의미 계약이다.

- 대상 정규 의미가 명시적이어야 한다.
- 승인 문구가 저장소 내부에서 관리되어야 한다.
- 어떤 현재 상태를 기준으로 승인됐는지 검증 가능해야 한다.
- 출처/권한 추적이 가능해야 한다.
- 금지 확장이 함께 관리되어야 한다.

---

## 6. 현재성 규칙

상세 설명 재료는 한 번 승인됐다고 영구 유효하지 않다.

다음 중 하나라도 바뀌면 기존 승인 재료는 자동으로 현재 상태로 간주하면 안 된다.

- 정규 의미 문구
- 의미 식별자
- 조건/한정
- 적용 한계
- 필수 동반 의미
- 분기 구조
- 관련 상충 관계에서 설명에 직접 의존하는 부분

후속 구현은 최소 다음을 비교해야 한다.

```text
current canonical meaning state
vs
approved detailed material baseline
```

불일치하면 해당 재료는 노후화 상태다.

노후화된 재료를 일부만 빼고 상세형을 계속 출력하지 않는다.

---

## 7. 완전 준비 판정

상세형은 결과 전체 단위로 준비 상태를 판정한다.

### 준비

모든 사용자 노출 핵심 의미 단위에 필요한 상세 설명 재료가 현재 상태이고, 필요한 조건/한계/동반 설명이 모두 준비됨.

### 불완전

다음 중 하나라도 존재:

- 필요한 승인 재료 누락
- 승인 재료 노후화
- 필요한 조건 설명 누락
- 필요한 적용 한계 설명 누락
- 분기/상충 설명을 사용하려 했지만 승인 재료 부족

### 대상 외

현재 상세형 활성화 범위 밖의 읽기 영역.

후속 구현에서 상세형을 활성화할 때:

```text
ready
→ detailed

incomplete / stale / unsupported
→ entire result standard
```

부분 상세형 + 부분 기본형 혼합 출력을 기본 정책으로 허용하지 않는다.

---

## 8. 렌더링 규칙

상세형의 렌더링 순서는 기존 공식 읽기 계획을 따른다.

상세형이 할 수 있는 일:

- 기준 의미 뒤에 승인 설명 블록 추가
- 조건/한계 승인 설명 표시
- 승인된 분기/상충 설명 표시

상세형이 할 수 없는 일:

- 섹션 재배치
- 의미 단위 재정렬
- 의미 단위 병합
- 의미 단위 삭제
- 새로운 결론 추가
- 기존 확신 수준 강화
- 기존 분기 제거
- 기존 상충 해소

---

## 9. 언어 모델 경계

상세형 추가 설명은 언어 모델 자유 생성의 근거가 아니다.

후속 상세형 공식 출력 경로의 기본 목표:

```text
approved detailed material
→ deterministic rendering
→ zero semantic generation
```

언어 모델을 사용한 표현 변환이 향후 필요하다면 별도 권한 계약과 의미 보존 검증을 먼저 가져야 한다.

그 전에는 상세형 활성화 근거로 사용하지 않는다.

---

## 10. 제품 응답 경계

사용자 제품 응답에 다음 내부 정보를 노출하지 않는다.

- 상세 재료 등록소 식별자
- 상세 준비 상태 내부 코드
- 누락 재료 식별자
- 노후화 이유
- 기준 해시
- 내부 권한 식별자
- 기본형 대체 내부 사유

제품에는 이미 결정된 공식 결과만 전달한다.

---

## 11. 이번 단계의 런타임 상태

이 문서 병합 후에도 다음 상태를 유지한다.

```text
concise  = 조건부 실제 지원
standard = 지원
detailed = 기본형 안전 대체
```

특히 현재의 `missing_expansion_material` 안전 대체를 이번 단계에서 제거하지 않는다.

상세형 활성화는 별도 후속 구현과 검증을 거쳐야 한다.

---

## 12. 후속 구현 단계 제안

다음 구현 단계는 이 문서가 승인된 뒤 별도로 진행한다.

1. 상세 재료 정의 타입/등록소
2. 현재성 검증
3. 결과 전체 완전 준비 판정
4. 결정적 상세 렌더링
5. 기본형과 상세형 의미/근거/순서 동일성 검증
6. 누락/노후화 전체 기본형 대체 검증
7. 분기/상충 보존 검증
8. 제품 응답 내부 정보 비노출 검증
9. 공식 실행 경로 의미 생성 모델 호출 0회 검증

이 후속 단계 전까지 상세형은 활성화하지 않는다.
