## Important non-equivalences

I162 freezes the following non-equivalences:

- no derivative dependency found != independent normative provenance established;
- alternate witness of the same work != new authority;
- downstream retransmission != independent authority;
- search exhaustion != independence;
- candidate removal != automatic preservation of six-requirement coverage;
- replacement/rebinding != automatic inheritance of prior scope, ownership, bridge, contradiction, or provenance findings.

## Candidate removal and replacement

A candidate cannot be removed merely to make a provenance problem disappear. Any changed candidate set must re-demonstrate full six-requirement coverage and exact requirement ownership.

Changed evidence must also undergo the affected scope, semantic-bridge, contradiction, and provenance checks rather than inheriting old results silently.

## Prospective versioning

Any remediation that is eventually adopted must:

- be prospective;
- create a new candidate-set version;
- create a new input-package version;
- receive a new single-use evaluation authorization;
- execute the complete frozen nine-step evaluation sequence.

No part of that chain is authorized by I162 itself.
