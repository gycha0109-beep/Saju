## 1. Purpose

I19 showed that post-relation root effect cannot safely depend on the final day-master strength classifier without circular reasoning.

I20 therefore builds independent pre-classification evidence only.

```text
seasonal context
+ positional support context
+ rescue-relation candidates
!=
relative-force verdict
```

## 2. I20A — Seasonal phase and raw support positions

The month-branch element is used only as a source-bounded seasonal context.

Five phases:

```text
command element              -> 旺
what command element generates -> 相
what generates command element -> 休
what controls command element  -> 囚
what command element controls  -> 死
```

This produces an ordinal seasonal-context state, not a numeric strength score.

Per branch position, I20A also records raw positions of:

```text
visible same-element stems
visible resource stems
same-element branches
resource branches
```

No positional evidence is summed or weighted.

## 3. I20B — Clash seasonal-advantage candidate

Possible values:

## 4. I20C — Support-context categories

I20C separates kinds of support instead of turning them into additive points.

Named evidence:

```text
SAME_PILLAR_VISIBLE_SAME_ELEMENT_SUPPORT
EXTERNAL_VISIBLE_SAME_ELEMENT_SUPPORT
VISIBLE_RESOURCE_SUPPORT
ADDITIONAL_SAME_ELEMENT_BRANCH_SUPPORT
RESOURCE_BRANCH_SUPPORT
NO_TRACKED_SUPPORT_CONTEXT
```

A branch is not counted as its own additional same-element branch support.

This distinction matters because the cited methodology treats visible peer support and branch rooting as qualitatively different forms of support rather than interchangeable units.

The stage does **not** infer:

```text
support is effective
support outweighs the opponent
support rescues a root
participant wins clash
```

## 5. I20D — Clash rescue-relation routing

The source tradition contains cases where a combination or meeting relation can settle or redirect a clash, but also requires that such a relation have sufficient force and appropriate context.

I20D therefore detects only structural rescue candidates:

```text
SIX_COMBINATION_RESCUE_CANDIDATE
THREE_COMBINATION_RESCUE_CANDIDATE
```

A rescue candidate means only that a tracked relation structurally touches a clash participant.

It does not mean:

```text
clash neutralized
root preserved
root transformed
rescue effective
```

## 6. Source audit

### Seasonal phase

《三命通會》 records the five seasonal element phases in the order `旺 / 相 / 休 / 囚 / 死` according to the relation with the commanding element.

Reference:

- https://zh.wikisource.org/zh-hant/%E4%B8%89%E5%91%BD%E9%80%9A%E6%9C%83/%E5%8D%B7%E4%BA%8C

### Clash and support context

《滴天髓》 and 《滴天髓闡微》 make clash outcome conditional on relative flourishing/decline, roots, peer support, season, and surrounding context.

References:

- https://zh.wikisource.org/zh-hant/%E6%BB%B4%E5%A4%A9%E9%AB%93/03
- https://zh.wikisource.org/zh-hant/%E6%BB%B4%E5%A4%A9%E9%AB%93%E9%97%A1%E5%BE%AE

### Rescue relation

《滴天髓》 戰合論 gives examples in which a combination/meeting relation can settle movement or conflict, while the commentary requires contextual force before effect is accepted.

Reference:

- https://zh.wikisource.org/zh-hant/%E6%BB%B4%E5%A4%A9%E9%AB%93/28
