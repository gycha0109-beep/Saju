# R141 — Multi-relation stem/branch graph order-sensitivity corpus

Date: 2026-09-27  
Track: saju-research  
Status: research-only

## Purpose

R141 begins the Stem-branch interaction semantics frontier.

It does not create a new relation-effect resolver. Instead it tests whether a graph containing multiple governed stem and branch relation identities remains representationally stable when the same relation nodes are enumerated in different input orders.

The target failure mode is hidden order sensitivity such as first-match-wins, array-order precedence, sequential mutation, or relation-enum priority.

## Governed upstream boundaries

R141 is built on existing bounded research assets:

- R051: heavenly-stem five-combination pair identity only
- R055: six-clash structural/context axes only
- R056: punishment taxonomy only
- R059: six source-bounded interaction-conflict cases with no universal precedence
- source-scoped branch break: four direct positive pairs within one explicit source scope

None of these assets authorizes a chart-general effect resolver.

## Corpus shape

R141 contains 10 three-node graph cases.

- 6 cases replay all R059 direct conflict examples
- 4 cases are governed synthetic stress graphs
- 8 cases mix stem and branch relation nodes
- 2 cases are branch-only

Every three-node case is enumerated in all six possible input orders.

Total:

- 10 graph cases
- 30 relation nodes
- 60 order variants

## R059 direct replays

Each R059 direct case retains exactly one source-bounded actor-to-target assertion:

- 4 RESOLVES
- 1 CAN_REACTIVATE
- 1 MAY_BE_INEFFECTIVE

The directed source assertion is not converted into a global precedence edge.

A neutral R051 stem-pair identity node is added to each replay graph as an independent mixed-layer control. Its position in the input order must not change the bounded R059 assertion.

## Synthetic stress graphs

The four synthetic graphs cover:

- stem combination + branch clash + branch punishment
- source-scoped branch break + branch clash + branch meeting
- two stem-combination identities + branch clash
- branch meeting + branch clash + branch punishment

Synthetic co-observation edges explicitly carry no precedence and no settled effect.

These graphs are not claims that a particular historical source chart exhibits all listed relations. They are research fixtures constructed from already governed relation identities.

## Order invariance contract

For every graph, all six input orders must preserve:

- the same canonical node set
- the same canonical edge set
- the same source-bounded assertion signature, when one exists

Changing enumeration order must not emit:

- a first-node winner
- global relation precedence
- first-match short circuit
- sequential relation mutation
- numeric relation weighting
- graph settlement
- executable output

## Important distinction

A source phrase such as a meeting resolving a clash is a bounded directed assertion for that source case.

It is not equivalent to:

- MEETING always precedes CLASH
- COMBINATION always resolves CLASH
- CLASH always resolves MEETING
- relation type order determines settlement
- the first detected relation mutates the chart before later relations are considered

R059 explicitly blocks those generalizations, and R141 preserves that boundary under graph reordering.

## Authority

R141 remains research-only.

It does not authorize:

- effective stem combination
- transformation
- generalized clash effect
- punishment harm
- generalized branch-break effect
- global relation precedence
- total relation ordering
- numeric relation weights
- executable graph settlement
- engine admission
- InterpretationClaim emission
- preview promotion
- production promotion

R142 will separately investigate competing heavenly-stem combination target cases rather than using R141 order tests as a target-selection resolver.
