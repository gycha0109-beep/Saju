## Render-first decisive page map

### Printed p.72 / physical PDF 73 — source-authored palace/Yukchin boundary

The Yukchin chapter defines family-role semantics and explicitly says the reader should first judge the success/failure of the relevant palace structure and then consider `Star`, meaning Yukchin. It also warns that palace-only judgment is insufficient because a palace can appear unproblematic while a Yukchin relationship is problematic.

This is decisive because the source itself keeps:

```text
palace layer
+
Star / Yukchin layer
```

as distinct layers that must be combined.

The spouse-palace layer is therefore not declared a replacement for spouse-star/Yukchin semantics.

### Printed pp.73-81 / physical PDFs 74-82 — sex-conditioned Yukchin semantics

The method explicitly applies sex distinctions to Yukchin classification. It assigns Wealth in the male-native frame to roles including father and wife, while Officer in the female-native frame includes husband semantics. Multiple male/female diagrams and examples continue that allocation.

The important boundary is not merely historical terminology. The manual instructs the reader to use the sex-sensitive Yukchin relations in actual interpretation.

### Printed p.104 / physical PDF 105 — sex-common spouse-palace location layer

The palace chapter explicitly assigns:

```text
Year Branch  -> ancestor palace
Month Branch -> parent palace
Day Branch   -> spouse palace
Hour Branch  -> child palace
```

The Day-Branch spouse-palace assignment itself has no native-sex branch. This is a genuine sex-common positional layer.

### Printed p.105 / physical PDF 106 — operational spouse-benefit reading

The manual makes the spouse palace executable rather than merely naming a location. It evaluates spouse benefit from the Day Branch when the specified auspicious/root conditions are present.

Therefore:

```text
sex-common spouse-palace location layer = YES
operational natal spouse-palace reading = YES
```

### Printed p.106 / physical PDF 107 — spouse-palace clash reading

A clash to the Day-Branch spouse palace is used as evidence for spouse discord. This independently confirms an operational spouse-palace reading layer.

### Printed p.115 / physical PDF 116 — palace and Wealth used together in application

A later applied example identifies Day Branch as spouse palace and then interprets Wealth entering/combining with that palace in a woman-related reading.

This matters because it demonstrates the source's actual application pattern:


not:

```text

```

### Printed pp.118-119 / physical PDFs 119-120 — sex-conditioned spouse semantics remain late in the manual

The late summary material still associates Wealth with father/wife roles and Officer with husband/child roles, and the accompanying prose continues those role semantics.

Thus the sex-conditioned spouse layer survives after the palace chapter and through the later application material.
