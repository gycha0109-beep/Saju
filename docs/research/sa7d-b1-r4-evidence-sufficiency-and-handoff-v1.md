# SA-7D-B1-R4 — 역사 十神 계산 증거 충분성 심사 및 반환 계약 v1

> Watchtower-Track: `saju-research` · 연구 반환용, **실제 제품·API·Reader·Engine·Official·Monthly·Bridge 권한 없음**. `sourceSupportGrade=INSUFFICIENT` for **8/8**, `bridgeReentryReady=false`, `Production=HOLD`.

## 1. 이 라운드의 결정: 무엇을 위해 어떤 증거가 충분한가

R4는 `甲일간 × 특정 年干 = 十神`을 산출하는 **분류 알고리즘**과 역사적 실제 연운 **사용례**, 현대 개인 운세 **의미 해석**을 다른 성질의 주장으로 분해했다.

| 주장·사용 목적 | 필요한 최소 증거 | 현 시점의 충분성 | 제품 승격? |
|---|---|---|---|
| **S1: 고전에서 日主→他干 十神 분류명이 존재함** | 정확한 역사 판본의 원문·일간 역할·단독 명칭 L1-EXACT | **7/8 충족**, 甲乙는 劫財敗財 그룹/敗財 방향 문맥 때문에 단일 `劫財` 미결 | 아니오 |
| **S2: 고전에서 流年干을 日干에 대비하는 계산 방법이 존재함** | `流歲取天干` 또는 `推流年法`의 직접 방법 문맥, 生剋 방향 설명 | **범위 한정 충분**: 明刻 『三命通會』 p2 + 1937 『命理探源』 p79–80 다른 일간 검증 | 아니오 |
| **S3: 특정 甲日×특정 유년×十神명을 저술자가 실제로 기재함** | **同一 역사 인쇄 문맥의** 일간+연도+십신명 L2-C | **1/8 충족**, 나머지 7건 부족 | 아니오 |
| **S4: 일반 분류를 甲日의 모든 유년 干으로 일반화하는 역사적 계산 해석** | S1 + S2 + 정확 生剋陰陽 정의 + 저술/학파 사이 **compatible bridging proof**, 용어 충돌 해결 | **조건부 연구 추론만 가능**, 브리지 가교/명칭 체계 승인 부족. `L2-D` 조합을 새 `L2-C`로 쓰지 않음 | 아니오 |
| **S5: 현대 상품에서 '해당 연도 재물·직장·인간관계 변화'를 말해도 되는가** | S1–S4 외에 제품의 사실/비사실 표현 구분, 현대 해석 정책, 다른 트랙의 독립 승인 | **미충족**, 역사자료는 현실 미래 사건 예측 정확성의 실증이 아님 | **HOLD** |

**핵심 결정:** **제품의 십신명 계산 기능에 8개의 개별 고전 사건 사례가 논리적으로 필수라고 단정할 수 없다.** 일반 함수 관계의 정의와 시간 입력의 적용 규칙이 검증되면 *계산 계약*을 별도 심사할 수 있다. 그러나 **개별 문헌 용례가 없는데 저술자가 그 표현을 직접 사용했다는 역사적 주장은 할 수 없다.** 또한 알고리즘 정합성 ≠ 개인의 미래 사건 예측력.

## 2. 서로 다른 두 가지 합격 경로

### T-COMP: 십신 **분류 계산** 심사 후보 (연구 단계만)

사주 연간의 이름을 산출하는 **분류·라벨링 API의 계산 계약**을 논의하기 위한 필수 질문:

- Q1: `日干`·`流年干` 역할이 입력/계산에서 바뀌지 않는가?
- Q2: 10천간의 오행·음양·生剋 방향 및 `同類` 분기 규칙이 **하나의 지정된 명칭 체계**로 일관되는가?
- Q3: 역사적 `敗財`·`劫財`와 현재 십신의 `겁재`를 매핑한다면 그 **명시적인 convention/mapping 정책**이 있는가? 인쇄원문 자체의 역사 라벨을 무단 변경하지 않는가?
- Q4: 출생년주/월주/일주/시주와 실제 流年의 연간을 구분하며, 入春/교체시점의 계산 책임이 별도로 배정되어 있는가?
- Q5: 분류 결과와 吉凶 판단·십신의 현대 역할/재물 설명이 분리되는가?
- Q6: 소스 간 source edition, 시대, raw label의 차이를 추적할 수 있는가?
- Q7: 경계 사례·동일·반대 음양·正/偏 방향 전환의 deterministic regression test가 구비됐는가?

**판정: T-COMP는 연구용 제출 후보로 구성 가능하나 지금 승인되지 않음.** 새 코드나 공식 TS 타입은 생성하지 않는다. 甲乙 이름 정책과 호환성 근거, 제품 책임 트랙의 합의가 먼저다.

### T-HIST: 고전 **직접 개별 연운 증거** 심사

이 경로의 증거 계약은 변경하지 않는다. 원문에서 *정확히 어느 특정 년을 무슨 십신으로 불렀는가*를 확인할 때마다 L2-C +1로만 기록. 현재 B1의 8종 중 `甲日辛亥年 正官` **1/8**. 별도 A2 庚年偏官·戊年偏財 2건은 신규 8개 집계 제외.

**T-COMP 도출가능성의 학술적 합의가 나와도 T-HIST의 1/8은 그대로다.**

## 3. 상호 반례와 자동 승인 차단

| CASE | 입력·조건 | 승인 불가한 처리 | 요구 판정 |
|---|---|---|---|
| S-01 | 甲木 일간, 丁流年. L1 `甲見丁傷官` + M1 `流歲取天干` | "『三命通會』가 丁流年을 직접 傷官이라고 명명했다" | `L2-D_CONDITIONAL`, `L2-C=NO` |
| S-02 | 甲日遇乙, 明刻 `劫財敗財` | `劫財` 단독 역사 명칭 PASS | `L1_EXACT=HOLD`, grouped 원문 보존 |
| S-03 | 甲子日見甲子太歲 | `比肩` 문구가 등장했다고 인용 | 이름 없는 太歲 증거, L2-C HOLD |
| S-04 | 庚金日主 乙卯年 正財 | 甲일간 직접 유년 정재 사례로 재할당 | 他日干 별도 기록 |
| S-05 | 甲木日元 辛亥年 正官之鄉 | 현대 "승진/역할 상승" 사건 공식 예측 | 역사적 L2-C 1건, 현대 L3 HOLD |
| S-06 | PDF 미리보기 JPG SHA256 성공, PDF full binary 미취득 | 원본 PDF 전체 검증 완료 주장 | `DERIVED_IMAGE_VERIFIED` only |
| S-07 | 웹 『千里命稿』 이론篇과 1935 第一集 인쇄 PDF | 판본/章/인쇄페이지가 동일하다고 무증거 합치기 | provenance split |
| S-08 | 1937 계산 一例와 明刻 甲乙 명칭 충돌 | 모든 시대에 음양 十神 단일명 같다고 합성 | `SCHOOL_BRIDGE=UNPROVEN` |
| S-09 | 年干은 계산됐으나 地支/대운/용신 입력 없음 | 十神이 유년의 모든 吉凶·현실 결과를 결정 | 설명/예측 금지 |
| S-10 | 일반 규칙 7개에 L1 있음 | `L2-C=8/8` 또는 `sourceSupportGrade=SUFFICIENT` | fail closed |

S01–S10은 **문서에서 검토한 논리적 반례 목록**이고 실제 자동 실행 테스트 결과라고 해서는 안 됨.

## 4. 다음 소유권/트랙에 넘길 수 있는 것과 없는 것

**반환 가능:** (1) 네 저술의 시대·파일 ID·장 위치를 구분한 명례 색인, (2) L1 7/8 원장, (3) L2-M 방법의 판본별 출처, (4) 1건의 직접 L2-C, (5) 이름 충돌과 합성 후보, (6) T-COMP 계산 심사를 위한 입력·결과 범위 질문, (7) P2/P3 검색 기각 기록.

**반환 불가:** `sourceSupportGrade`의 임의 등급 상향, `bridgeReentryReady=true`, 新年度 사건 해석, 엔진·리더의 실제 적용, 『三命通會』가 **모든 甲日 유년의 십신을 하나하나 직접 열거했다**는 설명, 甲乙 고전이 단독 劫財를 사용했다는 단정.

다음 소유권 경계:
- **사주 Research:** 독립 인쇄증거 및 문헌의 계산법/용어 충돌 판정.
- **사주 해석/엔진 계약 담당:** 십신 계산을 제품에서 구현·사용할지 결정할 때 canonical label mapping, 時間 boundary, event-prediction prohibition 검토 (여기서 승인하지 않음).
- **Bridge·Commerce·UX 담당:** 별도 제품 표시/권한 심사 없이는 연구 결과를 사용자 운세 설명으로 자동 편입하지 않음.
- **CI 운영:** 새로운 대형 상시 스캔 workflow를 요구하지 않음. 증거가 정확히 특정될 때만 범위 제한 검증을 검토.
