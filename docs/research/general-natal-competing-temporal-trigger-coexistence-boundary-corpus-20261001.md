# R158 — Competing Temporal Trigger Coexistence / Settlement Boundary Corpus

> Date: 2026-10-01  
> Status: RESEARCH COMPLETE CANDIDATE  
> Scope: simultaneous temporal trigger observations, order invariance, settlement boundary  
> Track: saju-research

## 1. Research question

R157 established that temporal trigger classes may be preserved as source/provenance observations without becoming executable trigger predicates.

The next question is:

> What happens when more than one trigger class is present at the same time?

R158 answers only the representation question.

It does not resolve the competing triggers.

## 2. Core distinction

R158 enforces:

    trigger coexistence
    != trigger settlement
    != trigger precedence
    != semantic winner
    != deterministic event

Multiple observed trigger classes can be retained in one context without deciding which one wins.

## 3. Trigger-set corpus

R158 contains six trigger sets:

1. transparency activation + natal–luck meeting activation
2. structural-change trigger + break trigger
3. break + rescue
4. break + counterforce
5. rescue + counterforce
6. break + rescue + counterforce

The five two-trigger cases produce two order variants each.

The three-trigger case produces six order variants.

Total:

    6 trigger-set cases
    16 order variants

## 4. Canonical trigger-set identity

Every permutation of one trigger set produces the same canonical trigger-set key.

Therefore:

    [BREAK, RESCUE]
    [RESCUE, BREAK]

are the same semantic input set for R158 representation purposes.

Input enumeration order does not become semantic precedence.

## 5. R154 order-invariance bridge

R154 already established for temporal-layer conflict testing that:

- input order does not imply semantic precedence;
- evaluation order does not imply causal order;
- first match does not win;
- last applied does not win;
- sequential mutation does not create authority;
- numeric temporal weights are unauthorized;
- relation count is not severity.

R158 applies those governance boundaries to competing trigger representation.

It does not create a new settlement algorithm.

## 6. R143 coexistence bridge

R143 established:

    structural coexistence != settlement

for branch combination/clash cases.

It also preserves source-bounded settlements without turning them into global precedence.

R158 uses that only as a governance analogy:

    sourceBoundedRelationAnalogyOnly = true

A relation-level source-bounded settlement does not authorize a generic temporal-trigger winner.

## 9. What R158 establishes

R158 establishes only that:

- competing trigger observations can coexist;
- trigger-set representation can be order-invariant;
- coexistence is distinct from settlement;
- trigger enumeration order is distinct from semantic precedence;
- break/rescue/counterforce coexistence can be represented without a winner;
- three-way trigger coexistence can be represented without aggregation.
