## 0.1. 2026-11-24 범위·상품 권한 정정

이 문서는 **11개 독립 해석 영역 중 6개를 먼저 완성하는 구현 트랙**이다. 전체 해석 영역이나 전체 상품 카탈로그를 정의하지 않는다.

- 이번 구현 범위: 직업·커리어, 사업, 재물, 일반 연애·관계, 연간, 월간.
- 별도 영역으로 유지: 가족 T8, 배우자 T8, 궁합 T10, 질문별 T11, 대운·인생 단계.
- 궁합 T10은 별도 내부 5단계 해석·발급·Reader 트랙(#2809)에서 완료 판정된 범위다. 이 여섯 메뉴 트랙에 합치거나 다시 구현하지 않는다.
- General Natal은 공통 원국 기반이며 별도 유료 메뉴가 아니다.
- 사업은 독립적인 T8 해석 범위로만 다룬다. 이 설계는 사업의 독립 상품·SKU·가격·Offer·Entitlement를 승인하거나 생성하지 않는다.
- MyeongHa의 2026-11-06 카탈로그 코드에는 Business 단품 엔트리가 남아 있지만, 2026-11-24 제품 소유자 지침에 따라 독립 상품으로 확정하거나 활성화하지 않는다. 기존 코드와 최신 제품 지침의 정합성은 별도 제품 카탈로그 권한으로 다루며, 이 설계에서 상품 코드를 변경하지 않는다.
- 여섯 메뉴는 14개 코드 Offer 엔트리나 11개 해석 영역 전체를 대체하지 않는다. Family/Spouse/Compatibility/Question-specific/Daewoon을 폐기하거나 미구현으로 단정하지도 않는다.

이 설계의 완료는 여섯 메뉴의 해석·근거·Reader 경로를 해당 범위 안에서 완성한다는 뜻이다. 전역 Production Interpretation Authority, 전체 11개 영역, 실제 결제·공개 판매·운영 배포의 완료를 뜻하지 않는다. Saju 전역 Production Authority는 현재 별도 감사에서 계속 BLOCKED다. 기존 관계 T8의 좁은 서명 발급 경로도 전체 메뉴 권한으로 확대하지 않는다.

## 1. 완성 목표와 범위

### 1.1 이번 트랙에서 완성할 메뉴

| 메뉴 | 해석 범위 | 엔진 계층 |
|---|---|---|
| 직업·커리어 | 일하는 방식, 역할, 책임, 환경, 성과를 만드는 방식 | T8 Career |
| 사업 | 산출, 교환, 운영, 자원, 의사결정, 협업 | T8 Business |
| 재물 | 자원 형성, 교환, 유지, 배분, 지출과 책임 | T8 Wealth |
| 연애·관계 | 표현, 상호작용, 약속, 역할, 경계와 조율 | T8 Relationship |
| 연간 | 해당 연도의 원국·대운·세운 상호작용 | T9 Annual |
| 월간 | 해당 월의 절입 구간별 원국·대운·세운·월운 상호작용 | T9 Monthly |

원국 네 메뉴는 공통 원국 판단을 사용한다. 연간·월간은 해당 원국 해석을 시간 구간에 연결한다. 공통 원국 판단 자체를 별도의 유료 메뉴로 추가하지 않는다.

### 1.2 이번 완료 범위에서 제외

- 궁합(T10), 질문별 풀이(T11), 가족·인생 단계 메뉴
- 모든 명리 학파의 통합이나 모든 고전 규칙의 전산화
- 전체 신살 목록의 완전 구현
- 결제·가격·환불·운영 인프라 전체 개편

단, 여섯 메뉴의 실제 공식 발급·Reader 연결은 완료 조건에 포함한다. 결제·운영 전체의 출시 판정은 별도 트랙이다.

### 1.3 '완료'의 의미

완료는 모든 명식에 모든 주장을 억지로 출력한다는 뜻이 아니다.

- 채택한 명하 해석 방법이 버전으로 고정되어 있다.
- 각 메뉴가 해당 분야에 필요한 실제 근거를 사용해 고유한 결론을 만든다.
- 근거가 충분한 내용은 끝까지 설명한다.
- 특정 판단만 미확정이면 그 판단만 보류하고 나머지 해석은 계속 제공한다.
- 같은 입력과 같은 규칙 버전은 같은 의미 결과를 만든다.
- 최종 한국어 문장까지 계산 사실·규칙·방법론·근거를 역추적할 수 있다.

**고정된 해석 개수나 '중심 1개 + 보조 2개' 같은 숫자 조건은 사용하지 않는다.** 메뉴별 필수 의미 영역과 실제 근거 충족 여부로 완성도를 판단한다.

## 2. 기존 엔진을 그대로 사용한다

새로운 명리 판단 엔진이나 두 번째 공식 해석 경로를 만들지 않는다.

```text
Canonical Saju Snapshot
        ↓
T0 구조 사실
        ↓
T1 구조 균형 / T2 일간 강약
        ↓
T3 격국 / T4 용신 방법론 (필요한 메뉴·규칙에서만 사용)
        ↓
T5 십신 해석 / T6 천간·지지 상호작용
        ↓
T8 직업·사업·재물·관계 종합해석
        ↓
T9 연간·월간 시기 해석
        ↓
기존 Claim Graph
        ↓
메뉴별 Reading Profile / Evidence Selector
        ↓
ClaimNarrativeProfile / 결정론적 문장 구성
        ↓
```

재사용 대상:

- `src/interpretation/interpretation-engine.ts`
- `src/interpretation/rule-registry.ts`

- `src/interpretation/claim-graph.ts`
- `src/narrative/evidence-selector.ts`

Claim Graph, Evidence Selector, Narrative Profile을 대체하는 새 계층은 만들지 않는다. 제품 계층이 명리 의미를 새로 만들어내는 Mapper도 추가하지 않는다.

## 3. 공통 판단 규칙 설계

### 3.1 T0 — 계산된 사실

계산 엔진이 확정한 사실만 전달한다.

- 네 기둥, 십신, 지장간
- 월지와 월령 관련 구조
- 투간·통근에 필요한 원시 사실
- 합·충·형·파·해·삼합·육합·천간 오합의 관계 후보
- 대운·세운·월운과 정확한 적용 구간

계산 사실과 명리적 의미를 같은 값으로 취급하지 않는다.

### 3.2 T1 — 구조 균형

다음 정보를 별도 근거로 보존한다.

- 계절과 월령의 환경
- 오행의 분포
- 생조와 극·설
- 투간과 지장간
- 독립 통근과 관계가 걸린 통근
- 관계가 겹친 뿌리와 독립적으로 남은 뿌리

단순 개수 합산이나 근거 없는 수치 점수로 강약을 정하지 않는다.

### 3.3 T2 — 일간 강약

일간 강약은 하나의 숫자나 단순 신강·신약 이분법으로 처리하지 않는다.

최소 판단 요소:

1. 월령·계절이 주는 기본 환경
2. 일간의 독립 통근
3. 천간과 지장간의 생조
4. 극·설 작용과 그 근거 위치
5. 합·충 등 관계가 통근·지원에 닿는지
6. 확인되지 않은 시각·시나리오가 있는지

출력은 근거별 지원·부담과 종합 상태를 보존한다. 강약 결론이 확정되지 않으면 해당 결론만 보류한다. T2가 필요한 T3/T4/T8 규칙은 그 입력 상태를 명시한다.

### 3.4 T3 — 격국

격국을 모든 방법론에 공통인 단일 전역값으로 만들지 않는다.

- 월령 선택 신호와 격국 후보의 정체를 구분한다.
- 후보의 정체, 성립 조건, 성패, 혼합 결과, 최종 상태를 서로 다른 단계로 다룬다.
- 명하가 실제 채택한 방법론과 그 방법론이 정한 조건이 있을 때만 해당 방법론의 격국 판단을 만든다.
- 복수 후보가 보인다는 사실만으로 복수 격국의 공존이나 우선순위를 확정하지 않는다.
- 판단 조건이 없는 복합 사례는 전체 풀이를 막지 않고 격국 관련 주장만 보류한다.

R131의 기존 경계는 유지한다. 이번 설계는 관측 신호를 격국 성립 사실로 바꿔치기하지 않는다.

### 3.5 T4 — 용신·희기

억부·조후·통관·격국 중심 판단을 하나의 계산식으로 섞지 않는다.

- 방법론별 용신 후보와 판단 근거를 보존한다.
- 각 방법론의 적용 조건을 별도로 명시한다.
- 방법론끼리 결과가 다르면 평균·다수결·숨은 가중치로 하나를 선택하지 않는다.
- 특정 분야의 결론에 실제로 필요한 방법론만 소비한다.
- 모든 분야에서 최종 용신 한 개를 필수 입력으로 강제하지 않는다.

### 3.6 T5 — 십신 해석

십신 이름을 단순 나열하지 않고 정확한 위치와 채널을 보존한다.

- 천간에 드러난 십신
- 지지의 대표 십신
- 지장간의 십신
- 월령과 연결된 십신
- 독립 통근 여부
- 동일 십신의 반복과 서로 다른 십신의 결합

동일한 십신이라도 위치·분야·다른 근거가 다르면 같은 의미라고 자동 처리하지 않는다. 반대로 위치가 다르다는 이유만으로 의미를 억지로 다르게 만들지도 않는다.

현재 Career T5의 정확한 십신 유형 및 계열 관계는 연구용 기반으로 존재한다. 이를 바로 Career T8 결론으로 승격하지 않고, 분야별 합성 규칙을 별도로 정의한다.

### 3.7 T6 — 천간·지지 상호작용

관계가 발견된 것과 그 관계가 실제로 작용한 것을 분리한다.

```text
관계 구조 확인
    ↓
해당 위치·참여자에 적용되는지 확인
    ↓
그 관계에 대해 채택된 효과 규칙이 있는지 확인
    ↓
효과가 확인되면 분야별 의미에 반영
```

- 합·충·형·파·해·삼합·육합·천간 오합은 관계별로 처리한다.
- 한 관계가 다른 관계보다 항상 우선한다는 전역 순위를 만들지 않는다.
- R133의 국소 구응 사례는 해당 조건에서만 사용한다.
- R143의 합충 공존은 접점 관측과 효과 판정을 분리한다.
- R051/R052에 따라 천간 오합·육합의 결속과 합화를 구분한다.
- 효과·합화·구응이 미확정이면 그 관계의 결론만 보류한다.

상호작용이 미확정이라는 이유로 이미 확인된 십신·계절·통근·분야별 근거까지 버리지 않는다.

### 3.8 T7 — 신살

이번 여섯 메뉴의 필수 기반으로 강제하지 않는다. 출처·적용 범위·검증이 갖춰진 신살만 해당 분야의 보조 근거로 추가할 수 있다. 신살 개수로 해석의 완성도를 판단하지 않는다.

## 4. T8 — 분야별 종합해석

T8은 공통 근거를 각 분야의 질문으로 바꾸는 단계다. 같은 원국을 사용해도 분야별로 소비하는 근거와 결론은 달라야 한다.

### 4.1 직업·커리어

| 의미 영역 | 답해야 하는 질문 |
|---|---|
| 일의 수행 방식 | 무엇을 만들고, 정리하고, 전달하는 방식이 두드러지는가? |
| 판단 방식 | 스스로 결정하는 부분과 기준·절차를 따르는 부분은 어떻게 나타나는가? |
| 역할과 책임 | 어떤 역할·책임 구조가 주요하게 관측되는가? |
| 업무 환경 | 협업, 독립, 조직 기준, 자율성의 관계는 어떠한가? |
| 가치 창출 | 산출과 결과를 어떤 방식으로 연결하는가? |
| 조율 지점 | 서로 다른 근거가 함께 있을 때 무엇을 조율해야 하는가? |

기존 T5 기반을 재사용한다. T6는 실제 효과 규칙이 승인된 범위에서만 Career 의미를 변경한다. 직업명·연봉·승진·취업 성공을 단일 명식 조건으로 단정하지 않는다.

현재 P2 T5 기반과 일부 T6 관측은 있으나, T8 Career 의미 합성 권한은 별도 설계·채택이 필요하다. 기존 Career T8 규칙을 새 개인화 경로의 대체재로 사용하지 않는다.

### 4.2 사업

| 의미 영역 | 답해야 하는 질문 |
|---|---|
| 산출·제안 | 어떤 결과물과 제안을 만들어 내는 구조인가? |
| 교환·자원 | 결과물을 자원과 교환하는 관점은 무엇인가? |
| 운영·책임 | 운영 기준과 책임은 어떻게 연결되는가? |
| 준비·실행 | 준비·학습과 실제 산출의 관계는 어떠한가? |
| 주도·협업 | 자기 결정과 공동 운영을 어떻게 구분하는가? |
| 지속 조건 | 운영에 필요한 자원과 관리 조건은 무엇인가? |

기존 `business-natal-multifactor-candidate`의 산출·재성·관성·인성·비겁 조합을 출발점으로 사용하되, 관측 채널과 실제 해석 효과를 구분한다. 단순히 여러 십신이 같은 채널에 있다는 이유로 사업 적합성이나 성과를 확정하지 않는다.

### 4.3 재물

| 의미 영역 | 답해야 하는 질문 |
|---|---|
| 가치 형성 | 어떤 산출·활동이 자원 형성과 연결되는가? |
| 교환 | 결과물을 자원으로 바꾸는 조건은 무엇인가? |
| 유지·관리 | 자원을 계속 활용하기 위해 무엇을 남기고 관리하는가? |
| 배분 | 개인 자원과 공동 자원, 현재 사용과 준비의 관계는 어떠한가? |
| 책임·지출 | 자원을 사용하는 책임과 부담은 무엇인가? |
| 보완 경로 | 재성 외에 산출·자원 유지의 독립 근거가 있는가? |

기존 재물 다요인 규칙과 지장간 연구를 재사용한다. 재성이 관측되지 않았다는 이유만으로 재물 풀이 전체를 비우지 않는다. 반대로 식상·인성만으로 실제 재산 규모나 수입을 확정하지 않는다.

### 4.4 연애·관계

| 의미 영역 | 답해야 하는 질문 |
|---|---|
| 표현·접근 | 친밀감을 표현하고 관계에 접근하는 방식은 어떠한가? |
| 주고받음 | 시간·수고·관심을 주고받는 구조는 어떠한가? |
| 역할·약속 | 책임과 약속을 어떻게 이해하는가? |
| 경계·조율 | 가까운 관계에서 각자 정할 부분과 함께 정할 부분은 무엇인가? |
| 긴장·완충 | 관계를 조율할 근거와 제약은 무엇인가? |
| 배우자 관련 | 배우자궁·배우자성 등 별도 적용 조건이 충족될 때만 제한적으로 해석 |

일반 대인관계와 배우자 해석을 한 규칙으로 합치지 않는다. T8 문단을 두 사람에게 각각 출력한 것을 궁합으로 취급하지 않는다. 결혼·이별·외도 등 특정 사건을 확정하지 않는다.

### 4.5 분야별 완성 판정

분야별 Reading Profile은 고정 문단 수가 아니라 의미 영역의 충족 여부를 확인한다.

- 해당 메뉴의 핵심 질문에 답하는 결론이 있는가?
- 결론을 지지하는 실제 독립 근거가 있는가?
- 중요한 반대 근거나 조건이 누락되지 않았는가?
- 해당 메뉴에 속하지 않는 근거를 가져와 결론을 대신하지 않았는가?
- 필수 입력이 미확정이면 해당 의미 영역만 부분 처리했는가?

선택적 보조 영역은 명식에 해당 근거가 없다고 해서 실패가 아니다. 필수 의미 영역이 비어 있으면 `partial` 또는 `insufficient_evidence`로 표시한다. 단순 Claim 개수로 `complete`를 판정하지 않는다.

## 5. T9 — 연간·월간 시기 해석

### 5.1 연간

연간은 다음을 분리한다.

- 서울 달력연도
- 입춘 기준 효력 연주
- 해당 시점의 대운
- 원국의 분야별 기반
- 연운이 실제로 접촉하는 원국 위치와 관계

연운 십신의 주제만으로 한 해의 길흉을 결정하지 않는다. 해당 연도에 실제로 적용되는 원국·대운 관계를 별도 근거로 연결한다. 달력연도와 입춘 경계 전후의 입력을 섞지 않는다.

### 5.2 월간

월간은 달력 월 전체를 하나의 간지로 뭉치지 않는다.

- 서울 시간대의 달력 월
- 해당 월의 정확한 절입 시각
- 절입 전·후의 반열린 시간 구간
- 각 구간에 실제 적용되는 월주
- 해당 구간의 대운·세운
- 각 운이 원국의 분야별 근거에 닿는지

월운이 세운의 의미를 자동 상속하지 않는다. 대운·세운·월운 사이의 연결은 그 연결을 다루는 규칙이 있을 때만 적용한다.

### 5.3 분야별 기간 해석

연간·월간은 별도의 운세 키워드만 출력하지 않는다. 원국의 직업·사업·재물·관계 기반 중 해당 기간에 실제로 활성화되거나 제약되는 부분을 분야별로 설명한다.

예를 들어 월운의 충이 확인되면 '충이 있다'는 문장만 내보내지 않는다. 어떤 원국 위치와 어떤 분야의 기존 근거에 닿는지, 그 효과를 해석할 규칙이 있는지 구분한다. 효과 규칙이 없으면 충돌 접점만 관측하고 결과를 만들어 내지 않는다.

## 6. Claim·Evidence·Narrative 연결

### 6.1 Claim

모든 새 의미 규칙은 다음 계약을 가진다.

- 구조화된 Claim Type과 Value Schema
- 정확한 입력 Fact Path 또는 upstream Claim Type
- 입력의 필수/선택 여부와 cardinality
- 방법론 버전과 적용 범위
- Rule 조건 및 출력 의미
- Source Reference와 직접 근거 위치
- 제한 조건과 금지 추론
- 시나리오·기간 결속

Claim value에는 최종 한국어 문단을 저장하지 않는다.

### 6.2 Evidence

최종 문단은 실제 실행된 RuleEvaluation과 Claim Graph에서 선택된 근거만 사용한다.

- 어떤 계산 사실을 사용했는가?
- 어떤 규칙과 방법론이 적용됐는가?
- 어떤 출처가 그 규칙의 근거인가?
- 어떤 반대·제한 근거가 함께 존재하는가?
- 어느 명식·기간·시나리오에 해당하는가?

문장과 무관한 출처를 붙이거나, 선택되지 않은 근거를 사용한 것처럼 표시하지 않는다.

### 6.3 Narrative

기존 `ClaimNarrativeProfile`과 결정론적 렌더러를 사용한다.

- Claim의 의미 선택과 한국어 표현을 분리한다.
- 같은 의미 서명은 같은 문장 계획을 만든다.
- 다른 의미 서명의 차이는 문장에 실제로 드러나야 한다.
- 문단 순서는 명시된 분야별 정책으로 정한다.
- LLM은 표현을 다듬을 수 있지만 Claim·명리 판단·사건 예측을 새로 만들지 않는다.
- 같은 내용을 표현만 바꿔 반복하지 않는다.

## 7. 명하 내부 해석 방법 채택 정책

### 7.1 외부 연구를 무한정 기다리지 않는다

`docs/product/43-internal-commercial-saju-interpretation-policy-20261113.md`를 따른다.

- 외부 학회 합의나 전문가 감수를 전체 출시의 보편적인 선행 조건으로 만들지 않는다.
- 이미 확보한 근거와 기존 연구 결과를 먼저 사용한다.
- 특정 조건의 효과가 확정되지 않으면 그 주장만 보류한다.
- 동일한 근거 공백을 이유로 같은 검색·검토를 반복하지 않는다.

### 7.2 내부 채택 규칙의 등록

명하가 채택하는 규칙은 다음 항목을 갖춘 버전으로 관리한다.

1. 규칙이 답하는 질문과 적용 범위
2. 실제 입력 사실과 계산 경로
3. 해석 조건과 출력 의미
4. 출처 및 정확한 위치, 출처가 뒷받침하는 범위
5. 예외·반대 사례·보류 조건
6. 긍정·부정·경계 테스트
7. 내부 채택 결정과 해당 버전의 내용 해시

출처의 provenance 등급을 실제보다 높여 적지 않는다. 명하 내부에서 채택한 해석은 내부 채택 규칙으로 명시하고, 이를 모든 학파의 보편 명리 규칙이라고 표시하지 않는다.

### 7.3 권한·출시 게이트

내부 해석의 채택과 공식 발급 권한은 별도 단계다.

- 규칙의 내부 채택은 정확한 규칙·방법론 버전의 검토 기록으로 남긴다.
- 기존 Reviewer Trust, Review Attestation, Rule Registry의 해시 검증을 유지한다.
- 현재 Production Gate가 요구하는 검토 수준과 2026-11-13 내부 상용 정책의 관계를 별도 정책 변경으로 명시한다. 검토 상태나 출처 등급을 코드에서 임의로 승격하지 않는다.
- 공식 발급은 기존 Saju/MyeongHa의 구매·권한·서명·Reader 경로가 실제로 통과한 경우에만 허용한다.

## 9. 실제 구현 순서

- 각 출력이 관측인지 확정 해석인지 구분하고, 연구용 상태를 유지한다.
- 통과한 뒤 PR 체인을 병합 가능한 상태로 정리한다.

**종료 조건:** 최신 누적 커밋 기준 CI Green, 이전 기능 보존, 연구용/공식 경계 명확. PR 체인의 각 선행 변경이 누적 검증에 포함되었는지 확인한다.

### 2단계 — 공통 해석 방법의 채택 범위 확정

- T1 구조 균형, T2 강약, T3 격국, T4 용신, T5 십신, T6 상호작용을 실제 코드·출처·방법론별로 분류한다.
- 여섯 메뉴가 반드시 소비해야 하는 입력과 선택적으로 소비할 입력을 분리한다.
- R131/R133/R143/R051/R052의 미확정 조건을 전역 차단으로 확대하지 않는다.
- 명하 내부에서 채택할 규칙과 관측만 유지할 규칙을 버전으로 정리한다.

**종료 조건:** 각 규칙이 적용 가능한 메뉴·입력·결론·보류 조건을 명확히 갖는다.

### 3단계 — 원국 T8 네 메뉴 완성

구현 순서는 공통 계약을 먼저 고정한 뒤 기존 후보를 재사용한다.

1. 재물: 기존 누락·산출·자원 유지 경로를 먼저 완성한다.
2. 사업: 산출·교환·운영·책임 축을 분야별 Claim으로 연결한다.
3. 연애·관계: 일반 관계와 배우자 해석을 분리해 각 적용 범위를 완성한다.
4. 직업·커리어: 기존 T5 기반과 허용된 T6 맥락으로 실제 Career T8 합성 규칙을 설계·채택한다. legacy T8를 개인화 경로에 섞지 않는다.

각 메뉴는 독립적인 Claim Type, Methodology, Rule, Reading Profile, Narrative Profile을 가진다. 공통 T5/T6를 재사용하되 다른 메뉴의 결론을 복사하지 않는다.

**종료 조건:** 네 메뉴 각각에 핵심 질문, 필수 의미 영역, 실제 근거, 반대 근거, 부분 지원 상태가 구현된다.

### 4단계 — 연간·월간 T9 완성

- 연간은 달력연도·입춘·대운·원국을 결합한다.
- 월간은 달력 월·절입 전후·대운·세운·원국을 결합한다.
- 해당 시기와 분야에 실제로 닿는 근거만 사용한다.
- 기간 간 자동 상속과 사건 예언을 만들지 않는다.

**종료 조건:** 기간 경계가 정확하고, 같은 운이라도 원국의 관련 근거가 다르면 설명 가능한 의미 차이가 생긴다.

### 5단계 — 공식 Reading 경로 통합

- 각 메뉴의 공식 Reading Profile이 T8/T9 Claim을 선택한다.
- Coverage는 시나리오별로 평가한다.
- 선택된 Claim과 Evidence Bundle이 실제 최종 문장에 연결된다.
- 중복 문단·다른 분야의 무단 전용·근거 없는 주장을 제거한다.
- 연구용 Preview와 공식 Reading 경로를 명확히 분리한다.

**종료 조건:** 여섯 메뉴가 동일한 공식 해석 엔진·Claim Graph·Evidence Selector·Narrative 경로를 사용한다.

### 6단계 — 최종 품질 검증

- 고정 500건과 10,000건을 동일 정의·동일 시드로 실행한다.
- 핵심 구조가 다른 대조 명식과 의미가 같아야 하는 대조 명식을 별도로 검증한다.
- 생시 미상, 절입·입춘 경계, 대운 전환, 복수 시나리오, 합충 공존, 근거 부족 사례를 포함한다.
- 실제 선택된 입력 지문과 최종 의미 서명을 비교한다.
- 동일 의미가 우연히 달라지는 경우와 달라야 할 의미가 같은 문장으로 합쳐지는 경우를 구분한다.
- 테스트는 코드 변경 후 필요한 묶음만 실행하고, 이미 통과한 전체 검사를 이유 없이 반복하지 않는다.

**종료 조건:** 최신 커밋에서 계산·해석 실행 오류 0건, 근거 불명 종합 주장 0건, 필수 의미 누락 0건, 설명 불가능한 차별화·충돌 0건.

### 7단계 — 공식 발급 및 최종 완료

- 실제 상품 요청에서 올바른 명식·메뉴·기간·해석 버전이 연결되는지 확인한다.
- 구매·권한·서명·중복 처리·Reader 재열람과 기존 보호 테스트를 확인한다.
- PR·문서·로드맵을 최신 구현과 맞춘다.
- 여섯 메뉴의 완료 증거가 모두 있을 때만 이 해석 트랙의 `ROADMAP_COMPLETE`를 선언한다.

## 10. 반복 연구를 막는 작업 규칙

동일한 미확정 사항을 이름만 바꿔 다시 조사하지 않는다.

각 미확정 사항은 반드시 다음 중 하나로 종결한다.

1. **구현:** 기존 근거와 명하 내부 채택 규칙으로 실행 조건을 정의할 수 있다.
2. **범위 제한:** 현재 근거로는 효과를 확정할 수 없으므로 해당 주장만 보류한다. 다른 메뉴와 독립적인 근거는 계속 제공한다.
3. **방법론 선택:** 복수의 정당한 해석이 존재하므로 명하 기본 방법을 선택해야 한다. 선택 근거와 버전을 기록한다.
4. **실제 블로커:** 메뉴의 핵심 결론을 만들 수 없고 내부 채택으로도 해결할 수 없는 구체적인 누락이 있다. 이때만 사용자 결정 또는 특정 자료 확보를 요청한다.

새 연구는 기존 결론을 바꿀 수 있는 구체적인 새 증거, 새 계산 입력, 또는 명하의 방법론 선택이 생겼을 때만 다시 연다. 단순히 '더 연구할 부분이 남았다'는 이유로 같은 단계를 반복하지 않는다.
