# Saju ↔ 명하 첫 웹 출시 로드맵 경계 (2026-11-14)

> 목적: Saju의 **연구/계산/해석 의미**와 MyeongHa의 **14개 구매 상품·발급/결제/Reader**를 같은 개념으로 착각하지 않게 정리한다. [명하 최신 제품 범위](https://github.com/gycha0109-beep/MyeongHa/pull/3295) 및 [공통 게이트 정본 (동일 PR branch)](https://github.com/gycha0109-beep/MyeongHa/blob/docs/launch-six-character-all-saju-web-20261113/docs/LAUNCH_ROADMAP_CANONICAL_GATE_MATRIX_20261114.md).
> 출시 범위 분류의 추가 승인·상용 발급·판매 플래그 승격이 아니다. 각 트랙의 기존 구현·검증·권한·과거 기록을 보존한다.

## 1. 서로 다른 네 가지 대상

| 수량/범위 | 정확히 무엇인가 | 첫 출시 조건 |
| --- | --- | --- |
| **14개** | 명하에서 구매하는 승인된 `Offer`: 원국 4, 연/월 2, 관계 비교/결합 3, 패키지 5 | **14개 전부** 실제 결제·발급·권한·Reader/환불 검증 |
| **7개** | 해당 Offer에서 재사용하는 내부 Saju 의미 구성요소: 직업·사업·재물·연애·연운·월운·두 명식 관계 비교 | 실제 상품과 연결되는 각 구성요소별 계산·해석·정식 서명 발급 |
| **500명×8개 내부 메뉴** | `docs/ROADMAP.md`의 **7단계 품질 개선용 고정 표본**. 관계 비교 T10은 포함하지 않음 | **7단계 전부 최초 출시 전 완료**, 111건 누락과 연·월 반복·개인화 의미 검증 |
| **T10 별도 5단계** | 두 사람 관계 비교의 내부 상용 의미·충돌·한국어 풀이·정식 두 명식 발급 | 최초·추가·본인 연애+첫 비교 3개 상품의 별도 실제 검사 |

표본 8개 메뉴를 14개 판매 상품으로 치환하거나, 14개 Offer 모두 별도 연구 엔진이라고 간주하지 않는다. 기존 11개 연구/유료 메뉴·12개 표시 주제·폐기된 첫 단일 SKU는 해당 당시 문서의 역사적 개념이다.

## 2. 현재 실제 구현 책임

1. **Saju 7단계:** 같은 500건의 실제 계산→해석→Claim/Evidence→한국어 출력 차이를 진단·수정하고 500명 품질을 재검증한다. 외부 학술 전문가 승인/새 논문 자체는 필수 조건이 아니며 내부 채택 규칙의 일관성은 필수.
2. **T9 연·월운:** [PR #2762](https://github.com/gycha0109-beep/Saju/pull/2762)의 서울 기간·입춘/절입·원국/대운 및 채택한 한국어 해석과 정식 발급 서명을 검증한다. 내부 시안을 판매 권한으로 승격하지 않는다.
3. **T10 관계 비교:** [PR #2763](https://github.com/gycha0109-beep/Saju/pull/2763)의 기존 5단계와 두 사람 원본의 한정된 서비스 해석/모순 처리·서명 Official Reading을 완성한다. 추가 출판물/전문가 검토는 필수 근거가 아니다. 미지원 관계 결과 예언은 만들지 않는다.
4. **MyeongHa 소비자 경로:** [PR #3174](https://github.com/gycha0109-beep/MyeongHa/pull/3174)가 14개 Offer 구매·결제·발급/Grant·Reader/취소·환불을 소유. Saju가 결제나 운영 DB 권한을 중복 구현하지 않는다.
5. **관상:** `research/face-reading/whole-face-observation-reading-roadmap-20261105.md`는 별도 원래 연구 목표와 자체 출시/검증 계약을 유지한다. 이번 14개 **사주** Offer 웹 출시의 자동 전역 선행조건으로 연결하지 않는다. 관상 제품의 다른 확정된 별도 범위가 있으면 그 승인 경계를 따른다.

## 3. 출시 전/후 검증 경계

- **출시 전 필수:** 500명 재실행·중대 오류/근거 불명·개인화 의미 정합성, T9 기간/풀이, T10 두 명식·동의/정식 발급, 실제 상품별 서명·권리 검증. 고객이 지불하는 상품을 제공하지 못하거나 거짓 명식을 참조하는 경우는 출시 후로 미루지 않는다.
- **출시 후 확장:** 신규 학파/추가 문헌, 별도 관상 또는 신규 유료 메뉴, 장기 사용자 피드백을 바탕으로 하는 추가 개선. 이 분류로 기존 승인된 **500명 필수 품질 개선을 연기하지 않는다**.
- **출시 후 지속 측정:** 운영 고객의 오류/풀이 품질 모니터링과 경계 사례 개선. 이 역시 출시 전 500명/발급 검사 대체가 아니다.

## 4. 실행·완료 표기

- `Saju_QUALITY_7_STEPS_PASS`는 500명·7단계, `T9_ISSUABLE`는 연·월운 정식 발급, `T10_ISSUABLE`는 관계 비교 정식 발급, `MyeongHa_SALE_READY`는 결제/권한/운영까지 포함한 별도 판정이다. 이 문구들은 상태 **구분명**이며 코드 상수가 아니다.
- 각 트랙은 구현 사실/검증 수준/정책상 HOLD를 정확한 PR·CI·소스 버전에 묶어 관리한다. 어느 한 검증 PASS도 다른 완료를 자동으로 의미하지 않는다.
- 이미 입증된 검사는 정확히 같은 구현·배포 경계라면 재사용하고 중복 시험기를 개발하지 않는다. 변경된 경계만 다시 검증한다.
